# P7 原始 ALNS 搜索轨迹只读插桩：失败主要发生于生成阶段

**验证成功：** [GitHub Actions #38209767307](https://github.com/litao3237/uav-mec-patrol/actions/runs/38209767307)，原100次迭代、原 `ScreenedProxyObjectiveEvaluator` 的标量目标、原 ALNS destroy/repair/RRT与原物理 P1-R 均保持不变。**6个源码中的7个场景/工况对照均按原冻结 B-ALNS SHA-256精确复现终点**（7/7一致），测试与汇总无程序错误。所有S89–S96以前已用于研发，这次是**后验诊断**不是首次独立验证。

## 一、验证核心：原 ALNS 在搜索期间是否真的生成过可行的结构候选？

只读sidecar包装原 `ScreenedProxyObjectiveEvaluator`：先调用并原样返回原单标量目标值，再检查每一个第一次出现的离散 D 的 **old fast必要 → FIFO/EDF队列必要 → P2共享静态CPU必要 → P5带宽/CPU联合必要**。纯只读，结果不参与原ALNS接受、最优选择或RNG；另外独立累计插桩时间0.04–0.25s，不能计入正式优化用时。每个结构自带原目标分数与哈希，记录分层最优最多10个快照；对最多3个队列通过与最多3个联合通过的历史结构，在搜索完成**额外**调用原 CVX Stage1+Stage2 复核，不算原算法节约或收益。

**6个失败B源合计约595个已生成不同D**，旧fast仅62个通过，**FIFO/EDF只2个**，其中共享CPU只1个、联合CPU带宽也只1个，而且这个候选真实 Stage1仍 `infeasible`。对照正常工况的同样100次 ALNS搜索，**23个不同D能通过三个必要层次**，额外选取3个候选 Stage1+2均严格合格。

这里快照的额外 Stage1/Stage2 检查不用于原算法计算预算，也不证明 B-ALNS 丢弃了严格可行的精英候选；其用途是验证**候选生成的可行性分布**与输入负载/截止时间的根本差异。

## 二、与此前 P0–P6b 的研究结论之间的强联系

原 `src/uav_mec/algorithms/alns/hybrid.py` 先将原B探索最终 `best_solution` 送入原Stage1。如果该终点未严格合格，整个 ESI 精英结构强化被跳过（记录 `skipped=exploration_stage1_infeasible` 等）。旧 P0–P6b 大多在**这个已经搜索停止的失败 D 上**用另一条几层beam和不同邻域做条件性修复。如今对原搜索过程的完全同路径重放证明，在代表性高压失败工况内，**大部分时间连可进入连续优化的结构都未曾生成**。再加强P5的静态/联合可行性必要筛选，仅能拒绝不可能的D、节约CVX，不能自然生成更多可行 D。

原始单标量搜索代理会结合任务/资源约束惩罚，并非完全不考虑时限；但目前的destroy/repair和100迭代在高压工况下仍很难摆脱任务队列时间必要违反。应优先诊断每个原 `queue_failing` D 的违规任务与真实**采集位置、接触时间、局部FIFO前驱、EDF接触批次**的分布，设计能沿着违约链**直接降低必要时限超额**的结构修复，或在**初始解阶段**构建更少违规的路径/卸载状态；不要把“增加精确CVX次数”和“接触批次后验筛选”当成解决大部分失败源D的主机制。

## 三、下一轮可证伪的实验协议（不要立刻再堆无效算子）

1. 利用只读sidecar记录 `queue_necessary_reject` 中最关键的 FIFO/EDF 违约链，区分“至少有一个任务最早时限根本无窗”与“多前驱累计排队使某截止时间超额”，记录原B在搜索中是否朝减轻这些下界违反的方向移动。
2. 比较**同一初始解和同样种子**：仅替换ALNS中结构动作的“目标任务/接触选择”而不增精确求解次数，并在严格相同总wall-clock预算下评价产生队列必要通过的D频率、Stage1+Stage2严格合格率、UAV能耗。这里不能只是旧源后处理；必须在**整个 ALNS 搜索链**执行。
3. 与原正常Baseline S93 A129对照并保持完全一样的算子/RNG/时间：若能在高压工况稳定使某些D越过队列必要线，才值得测试后续共享带宽/CPU联合必要筛选与精英候选档案；否则优先重新检查问题建模和可行域大小。
4. 最后先冻结机制，再使用从未观察过的物理场景进行完全独立验证（注意 S97–S100 已被P6b首用，不能重用）；**算法随机种子嵌套于同一场景，不是独立场景。**

本研究给出的关键不是一个“增能耗收益”，而是对原 ALNS 探索严重缺少**物理上可行的离散候选**的直接可复现轨迹证据。它说明下一阶段应该从“后处理/候选筛选”转向“原搜索的可行结构生成/约束时窗机制”。`develop` 和投稿实验均保留不变。
