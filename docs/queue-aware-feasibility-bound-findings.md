## 一、为什么这个实验比调整搜索时间更有研究意义？

原代码 `fast_feasibility_precheck` 已有“每个任务给它最大的 CPU/带宽”的乐观完成时间下界，但**忽略本地 UAV 计算 FIFO 队列**，同时也没有完整计算同一 `(UAV,MEC)` 对连续接触批次的前驱完成时间以及之前上传接触对后续任务采集的影响。

前几轮固定结构重验发现：很多方案通过旧必要预检，却会在完整 Stage-1 被判为不可行。这不是单纯增加 2-opt* 可以解决的。

这次在独立实验分支中实现 `queue_aware_feasibility_precheck`，仅作为**新的离线诊断**与原预检进行对照，尚未接入正式算法。

## 二、下界构造与数学安全性

对固定的路径、接触、批次和本地/MEC 执行结构：

1. 每个上传批次 `v` 获得整个 MEC 的带宽上界，得到最乐观上传时间
   `tau_min(v) = data_mbit(v) / R(B_MEC, gamma_v)`。
2. 任务最早采集完成时间 = 固定路程/采集的基准时间 + 所有此前接触的最乐观上传耗时。
3. UAV 本地计算依照原模型中的 FIFO 顺序递推：
   `start_min(i) = max(collect_min(i), finish_min(previous local task))`，
   `finish_min(i) = start_min(i) + workload_i / f_UAV_max`。
4. 对同一 `(UAV,MEC)` 虚拟计算队列，各次接触批次按 FIFO 开始；每个批次内任务按原模型 EDF 顺序计算。将每个虚拟队列乐观地独享整个 MEC 的最大 CPU，递推出批次最早开始时间与任务最早完成时间。
5. 对原问题的截止时间、平均任务时延和 UAV 巡检周期执行必要下界验收。

**为什么不会误排除理论可行解？** 实际上传耗时不可能短于每批独享 MEC 带宽的乐观时间；实际本地 CPU 不可能超过各 UAV 最大值；实际 MEC 虚拟对的 CPU 不可能超过整个 MEC 上界。按照强制 FIFO/EDF 顺序递推，实际完成时间始终不小于上述下界。所以若一个时延下界已超过硬约束，该**固定离散结构**数学上不可能按当前资源模型满足该约束。

此下界仍忽略不同 UAV-MEC 对之间的 CPU/带宽竞争，因此**通过并不意味着实际资源可行**。该证明还以论文冻结的 `release_s=0` 与所建 FIFO/EDF 模型为前提，不能随意扩展到不同的释放时间或并行计算模型。

## 三、来自两轮 GitHub 已归档实验的 448 次复核

复核集合包括：
- **224 条**参数敏感性实验中每个配置都重新运行 B-ALNS/ESI 得到的**动态离散结构**；
- **224 条**对同一原始基准 D 保持路径、接触、卸载不变、仅改变计算密度/时限/带宽后重新求解连续资源的**固定离散结构**。

旧/新预检的“拒绝数”如下（含成功和失败实例；**不同方法、算法种子可能共享离散结构，不能把 448 次视作独立样本**）：

| 规模与结构来源 | 检查数 | 原乐观预检拒绝 | 新队列感知下界拒绝 | **额外安全排除** |
|---|---:|---:|---:|---:|
| K50，重新搜索的动态 D | 112 | 2 | 2 | **0** |
| K50，基准 D 固定 | 112 | 50 | 64 | **14** |
| K80，重新搜索的动态 D | 112 | 44 | 50 | **6** |
| K80，基准 D 固定 | 112 | 37 | 66 | **29** |
| **合计** | **448** | **133** | **182** | **49** |

**最重要的安全性检查：** 这 448 条结构中，原先已通过完整 Stage-1 严格残差验收的 **260 条**，新下界拒绝数为 **0**。对动态结构中有完整 Stage-1 物理时间快照的样本，还逐个检查了“新乐观完成时间下界不大于实际完成时间”，没有发现超出冻结数值安全容差的反例。

### 关键样例

**K80，计算密度 ×1.5，固定 B-ALNS 基准 D：**
- 旧的单任务必要预检只拒绝 **1/8**；
- 新的 FIFO/EDF 队列感知预检拒绝 **8/8**；
- 完整 Stage-1/Stage-2 真正严格合格也正好是 **0/8**。

说明先前 7 个“旧预检允许但凸优化后来失败”的结构中，队列感知必要时延下界能够提前发现问题，而不需要以实际连续资源求解结果倒推。最主要的新增证书通常来自原基准结构中大量本地计算任务的 FIFO 排队。

## 四、同时存在重要的负面证据

在 K50 重新搜索出来的 **112 条动态离散方案**中，新下界**没有**比旧预检多排除一个。这说明当前 ALNS 已经可能通过自己的构造/修复过程规避部分明显队列冲突；新预检即使数学上更强，也不保证实时运行时就能显著提升效率。

K80 重新搜索的 112 条方案中，仅有 **6 次**额外排除。是否值得将下界集成到主算法，仍要看**搜索过程中所有中间候选**的分布，以及计算新下界的实际 CPU 开销能否抵消节省的 CVXPY 求解时间。

注意 `optimal_inaccurate` 不应被视为数学不可行的直接证明；本次被新下界排除的任何一个固定方案，其严格证书来自队列递推超时，而不是求解器状态。

## 五、后续研究方向与不可越过的验证门槛

1. 保持 `develop` 不变，不直接将队列预检并入正式算法。先记录 B-ALNS/ESI 搜索中的中间候选，离线或在线对照“新旧预检命中数、每次评价 CPU 时间、严格 CVX 求解次数”。
2. 对此前严格不合格的高负载结构，利用**本地 FIFO / MEC 批次 FIFO/EDF 时延超额**作为针对性修复目标，构建路径—接触—卸载联合可行性修复，而不是只看单任务无队列的乐观时间下界。
3. 即使新筛选减少凸求解，也必须在**相同端到端时间**下验证严格合格率和总 UAV 能耗，不得用“额外剪枝数量”替代实际收益。
4. 还需对独立新任务空间分布与 MEC 接触配置做交叉测试，排除仅在 S61–S64 或当前拓扑上有效的风险。

这是一项**模型特有的正确性与效率机制**，但并不自动构成顶级期刊的充分创新；贡献的强度取决于能否导出真正更有效的约束驱动联合修复，并完成合理文献对比与等预算实证。
