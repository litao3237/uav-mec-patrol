# P11：区分“ALNS 搜索不到可行结构”与“原物理场景本身无解”的全实例必要界

## 为什么要研究全实例而非继续叠加 ALNS 算子？

P9首次场景S105–S108，`queue_chain` 严格Stage1+Stage2 8/40，相比原方法5/40；但在P10第一次新场景S109–S112上，原4/40、P9未保护`queue_chain`仅3/40，队列回退版也是3/40；新策略均0新增、反而破坏一个baseline原严格成功。局部队列任务/前驱优先 destroy 确有部分正样本，但无法称为稳定改进，进一步调参不科学。且最强计算×2、期限×0.8 profile 经常0严格可行：**必须先区分这些完整物理实例是否真正无解，否则ALNS失败率无法解释成算法应有可行解却未找到**。

此前 P2/P5 是**给定失败离散D后**的必要可行性界，只能断言某条路径/卸载方案不成立，不能断言整个任务规划实例无解。P11首次引入只使用原始**物理实例本身**的全局必要条件，不涉及任何离散D，也不求解CVX；一旦必要条件违反，所有合法离散路径、卸载与资源配额都无法满足原模型。**条件通过绝不证明整个实例可行**，尤其对多UAV的空间、通信和任务先后耦合相当宽松。

## 三个可审计的必要条件

记 (W_i) 为任务 Gcycles，(d_i)为原绝对截止时间，(r_i^{LB})为自同一 depot 出发、最有利UAV按直线飞到任务并完成采集的最早可能计算释放时刻。

### A. 任务单独乐观完成

对每个任务
[
r_i^{LB}+W_i/F_{max}le d_i,
]
其中 (F_{max}) 是全UAV本地CPU与MEC CPU中最快单个CPU。它忽略传输和排队、假设单个任务独占最强资源，因此违反就能证明整个原实例不可能严格完成。此条件在原论文实例生成器已有粗粒度统计，P11用于完整复核。

### B. 所有CPU合并成一个能任意分配给所有任务的乐观超资源池

记 (C_{pool}=sum_u F_u^{local}+sum_e F_e^{MEC})。对任意实数区间 ([a,b])，所有满足 (r_i^{LB}ge a) 且 (d_ile b) 的任务必须把完整工作 (W_i) 都安排在这个区间，所以
[
sum_{i:r_i^{LB}ge a, d_ile b}W_ile (b-a)C_{pool}.
]
只需枚举所有不同的 (ain{0}cup{r_i^{LB}}) 和 (bin{d_i}) 即可找到这类集合下最紧的候选区间；所有独立CPU可以幻想合并和动态调度，因此真实任务可行必满足这个区间容量条件。通过没有任何充分性含义。

### C. 多UAV全局路径采集资源的欧式最小生成树（MST）必要条件

对任意deadline (t)，所有必须在t前完成计算的任务自然已经在t前被采集。每架UAV从**共同depot**出发，它们在t之前的路线前缀几何连接所有 (d_ile t) 任务位置到depot；路程合计至少为集合 ({depot}cup {p_i:d_ile t}) 的欧式 MST 长度 (L_{MST}(t))。使用所有UAV的**最大飞行速度** (v_{max})，令全部无人机同时不间断工作，对路线飞行与采集服务时间有必要条件

在完整巡检周期处，同样要求全任务MST飞行+总采集时间不超过 (|UAV|cdot T_{cycle})；忽略所有回仓/接触/upload的额外时间，所以仍是安全乐观的必要条件。

### 严谨边界

三个必要条件分别忽略了资源竞争/卸载传输、实际任务归属与空间巡检顺序/先后依赖。数学证明只针对原**共同depot、每任务被采集一次、计算不能早于采集完成**的P1-R研究模型。若未来允许多个不同depot、多次部分计算前置或并行采集要重证。基础 energetic reasoning 与MST routing bounds 已有成熟调度/路由先例，P11本身是**模型可行域难度审计，不是新 ALNS 或投稿创新**。

## 冻结数据与决策门槛

只分析现有P9、P10已完整归档物理场景：S105–S108、S109–S112，每场景5个配对压力配置，**40个物理实例**（每个下含两个nested ALNS seed、这些种子不改变场景物理可行性）。对每个profile重新生成**完全相同**的原数据，比较原SHA-256，一例hash漂移就停止并报错；读取原方法与 P9/P10变体的真实严格Stage1+Stage2成功状态作为**阳性安全控制**，只要有原真实严格可行却被全局条件拒绝，CI必须失败、撤回该必要界。

输出每种profile的三类必要界最坏 demand/capacity ratio、是否数学证明整个实例无解、原算法真正严格可行的历史对照数，并独立保留数值不确定。

- 如果在 compute×2、deadline×0.8 证实大比例**全局无解**，这些场景无法作为考核搜索新算子可行率增益的合理benchmark，应改测试压力标定，不可通过放松原硬约束伪造正样本。
- 如果 **所有 global bounds均通过**，这只能说明本轮粗下界没有证明无解，**绝对不能说这些实例有解**。下一步应检查构造性可行解或增强带时窗、几何分配、MEC资源的全实例必要条件，再研究原`_insertion_option`与`_finish_repair`怎样改变FIFO/EDF队列完成时序。
- 原 `develop` 分支、原实验图表/硬约束/任务语义不允许被此项诊断修改。
