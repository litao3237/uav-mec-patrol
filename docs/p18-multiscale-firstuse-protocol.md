# P18 多规模首次独立验证协议（已在读取结果前冻结）

目标：检验 P17 的原MEC贪婪动作可采纳性插入，在K80以外的任务规模是否仍然改善原始ESI-ALNS严格可行率，同时审计代价和同源可行能耗。

**预注册实验**：新物理空间场景S125/S126/S127/S128，三任务尺度K30/K50/K80，UAV=5，MEC=2；每个场景×规模均执行 baseline、compute×1.5、deadline×0.9三个压力profile及算法seed173/174。共12个场景×规模块、72个嵌套profile/seed配对输入。四个空间场景为独立空间布局；相同场景下不同K规模/压力/算法种子有层级相关，不能当72个独立场景。

**三个冻结算法臂**：`original`（原始）、`proxy_sham`（每个Top3执行相同廉价原代理检查但保留旧rank1；控制计算成本）、`proxy_actionable`（原`_critical_local_tasks`+原`_strictly_better`候选旧contact复用代理排序）。P17其余两臂`proxy_contact`/`proxy_critical`已在S121–S124检验，这轮聚焦新机制的稳定性与等计算代价负对照，不能将缺失两臂误写为新完整五臂消融。

所有方法使用原相同初始D、破坏算子、修复算子数量、roulette/RRT、`ScreenedProxyObjectiveEvaluator`、原P1-R Stage1/Stage2及独立资源残差。B探索时钟目标6秒，ESI精英阶段最多2秒，**不是整个初始化/不可抢占CVX/最终严格验收的8秒硬截止**。实际端到端耗时另存；每个物理/种子同源报告Stage1+Stage2严格合格、原ALNS迭代/不同D、FIFO/EDF必要界及联合BWCPU必要界。能耗只在原/新**双方严格合格**的同源样本做差，避免不同分母条件均值造成错误结论。

**研究门槛**：至少在多个新场景及两个以上K尺度中出现真实严格新增且不过度丢失原成功；计算代价不能抵消探索能力；必须报告负面profile及完整墙钟。即使72条结果正向，独立空间布局仍只有4个，不足以支持统计显著/发表级普适优越性。失败时停止在旧Top3插入上继续加代理系数，改为诊断完整多任务修复顺序/模型可行域；不修改原正式`develop`和论文数据。

实验工作流：`p18-multiscale-firstuse.yml`。结果将归档 `p18-multiscale-summary-<run_id>`；任何失败job及不完整案例必须公开保留，不选择性剔除。
