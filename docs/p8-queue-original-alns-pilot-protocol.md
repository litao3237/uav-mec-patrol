# P8：将 FIFO/EDF 乐观时间必要约束直接用于原 ALNS 搜索评分

## 研究定位与预注册假设

此前原 P7 把 B-ALNS 100迭代按 SHA-256 重放，六个高压力失败样本访问约595个不同 D，只有2个通过严格FIFO/EDF必要时间下界。后处理P0–P6b中更强的CPU/BW剪枝虽减少CVX调用，却很少为原搜索**生成新可行离散结构**。当前 P8 不再对末端失败 D 做修补，而是直接修改原ALNS搜索评价，测试“在**整个搜索过程中**提供 FIFO/EDF必需截止时间残差梯度是否比原代理惩罚更容易形成队列必要合格D”。

**P8只是算法原型，不在 `develop`，不修改原物理参数、算子族、CVX/Stage2验收、原论文数据。**

## 三种严格可比的 P8 开发臂

1. `original`：原 `ScreenedProxyObjectiveEvaluator`，原原样 B和ESI搜索；100次迭代B的终点SHA必须与原历史 B-ALNS 冻结记录完全一致。
2. `queue_sum`：若原队列必要检查失败，则以所有任务/周期/平均时延的**归一化时限超额总和及最大超额**作连续惩罚；若检查通过，调用原 `ScreenedProxyObjectiveEvaluator`，保持严格原连续CVX修正。优先 queue-passing 状态是启发式搜索偏好，不是可行性证书。
3. `queue_max`：同样原资源模型和后段真实求解，仅让最大归一化时限超额对连续罚分的权重更高，验证是否总和型梯度被大量轻微违约任务淹没。

为避免把代价等同收益，对三组均加**相同只读shadow观察器**，完整记录所有生成的不同 D 在 queue/CPU/joint 三个必要层次的通过次数、观察器自身墙钟成本、原 ALNS 搜索真实时间，以及原Stage1和 Stage2 独立重求解的所有不合格/合格状态。原 ESI 精英强化仍只在原 Stage1合格时执行，且仍使用原 `contact_mode_intensification` 和最多2轮，未添加CVX配额、强化邻域或新建 ALNS destroy/repair。

### 严格实验证据门槛

- 开发 K80 已观察7个P7样本（6压力失败+1正常负载对照），全部先做**同样100次迭代**的A/B/C配对，既要看 `queue_pass/unique_D`，也看真正原Stage1+Stage2严格恢复以及端到端额外开销。**此试验只匹配迭代次数，绝不假装匹配真实wall预算**。
- 如果队列必要合格D明显增多但 Stage1+Stage2仍0/7改善，说明评分确实触达第一道屏障但后段CPU/BW/原算子不足；不能仅用 `queue_pass` 宣称提升。
- 如果队列必要合格D也没有增多，检查初始离散D和原始ALNS destroy/repair是否根本无法向有效时限结构移动；不得继续叠加更多惩罚权重掩盖结构性缺陷。
- 原ALNS与P8的 RRT 接受阈值随各自初始数值评分变化，故评估函数修改不可理解为只改变候选排序；选优后需另运行**相同搜索wall预算及一致冷却时间参数**对照，同时报告完整初始化、探索、精英和残差验收总实际耗时。
- 若研发样本支持某机制，再冻结到新独立物理场景S101以后（S89–S100此前已多轮观察）；同一场景的两个算法seed为嵌套重复，不是两个独立物理环境。

## 可能的算法创新性边界

FIFO/EDF排队感知、时间窗违反程度引导搜索、ALNS惩罚函数均已有成熟优化研究，不能将“在 ALNS 目标加截止时间惩罚”直接称为学术创新。后续若能把“乐观队列必要证明→针对性任务/接触重排→静态CPU/带宽联合资源分配”形成**有证明、有反馈、有消融、有完整等时间优势**的机制，才可能构成稿件中心贡献。
