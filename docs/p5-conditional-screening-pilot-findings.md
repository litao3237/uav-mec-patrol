# P5 通信—计算联合必要条件：同源条件修复配对消融（已完成）

**实验:** [Actions #38207053204](https://github.com/litao3237/uav-mec-patrol/actions/runs/38207053204)，校验+8个历史场景对照+完整汇总 **全部成功**，程序错误0。**研究样本 S85–S92 全部此前观察过，属于开发样本，不是未见场景。** 原始 `develop`、冻结B/ESI/资源严格验收及论文图表均不改变。

## 1. 冻结的四种候选筛选臂

- `queue_top3`：P1 原子+跨 UAV 相同离散候选池，乐观 FIFO/EDF 必要通过后按原字典序取前3；
- `static_cpu_top3`：相同候选池，用 P2 已证明的静态共享 CPU 份额必要界安全筛除后取前3；
- `joint_bw_cpu_12`：相同候选，先 CPU 必要拒绝，再用 P5 12个乐观向上带宽网格 DP 必要条件；
- `joint_bw_cpu_48`：与前臂完全相同，仅提高到固定48格。

每个源失败离散 D 的候选集合**共享生成一次**，Beam宽2、深度4、搜索生成软上限4s。所有方法最多3次原 Stage-1 精确候选求解，只对 Stage1合格的最优能耗候选做原 Stage1+Stage2独立残差最终验收。测算的“完整修复耗时”包含候选生成（四臂相同）、证书运行和真实求解，**不包含已预付的原始 B-ALNS 搜索时间**，因此不是全ALNS等端到端预算实验。

## 2. 主结果（严格两阶段恢复口径）

| 开发组 / 指标 | 队列筛选 | 静态 CPU 界 | 联合界12格 | **联合界48格** |
|---|---:|---:|---:|---:|
| S85–S88，22个失败D：严格恢复 | 4 | **5** | 5 | **5** |
| 同组 Stage1 精确接口次数 | 28 | 16 | 12 | **12** |
| 同组平均完整修复时间(s) | 1.639 | 1.428 | 1.350 | **1.367** |
| S89–S92，17个失败D：严格恢复 | 0 | 0 | 0 | **0** |
| 同组 Stage1 精确接口次数 | 11 | 5 | 2 | **0** |
| 同组平均完整修复时间(s) | 1.061 | 0.912 | 0.805 | **0.757** |
| **合计39个失败D：严格恢复** | **4** | **5** | **5** | **5** |
| 合计 Stage1 精确接口次数 | 39 | 21 | 14 | **12** |
| 合计平均完整修复耗时(s) | 1.387 | 1.203 | 1.112 | **1.101** |

**相对于旧静态 CPU 筛选：** 48格联合界额外节省 **9/21≈42.9%** 的真实 Stage1 接口调用，条件性完整修复平均用时减少约**8.5%**，并且没有失去原来的5个两阶段严格恢复。**相对于队列单独筛选：** 从39次 Stage1降至12次（约69.2%），但更多节约来自P2已有静态CPU界，不能把全部贡献归于P5。

**物理意义：** 对先前已经通过 FIFO/EDF和单独共享CPU测试的候选，联合带宽—上传时序—CPU最低份额条件能提供**更多确凿必要冲突**，实测计算约每候选1.7–2ms，减少对明知违反原模型必要条件的候选进行昂贵精确资源求解。

### 同样重要的负面结果

- 联合界的开发样本严格恢复仍 **5/39**，没有在 P2 的静态CPU必要界上新增严格成功；其价值暂时是**筛选节约**，不是新 UAV-MEC 路径能耗改进，也不是更强的结构修复。
- S89–S92 17个源 D 中，P5联合48格安全拒绝原本 P2 会送入 CVX 的全部5个候选，节省求解，但原方法这些候选本来均无法通过真实Stage1，**因此依然0严格恢复**。
- 虽使用“最多3次 CVX”的公平接口预算，联合证书耗时不同，且每个源结构可实际调用小于3次CVX；不能声称每种策略同实际CVX次数或相同全 ALNS 墙钟预算。

## 3. 下一道独立验证门槛

冻结此轮 N=48 **不再调参**，使用此前完全未参与开发的场景 S93–S96 和算法种子129/130，真实生成相同 B/ESI 物理源后，按原四臂进行配对对照。新的独立验证仍是**原 B-ALNS 失败结构后的条件修复**，不能冒充正式 ESI-ALNS全算法比较。记录真实每源完整修复墙钟时间、严格成功数、所有异常、数值不确定、原始模型输出、所需候选生成开销。

如果独立验证保持安全无误拒并稳定减少 CVX/CPU，P5可以形成一个可证明的**双资源必要剪枝组件**；但如果依然不能让原ALNS产生更多合格D，未来主算法研究应转向“证书驱动的带宽/接触时序/任务前缀联合重排”，不能只靠一个必要条件宣称优秀的 ESI-ALNS 能耗收益。
