- 17个失败结构中，只有 **3个**曾由任意一个 P3 修复臂送出 Stage-1 精确候选；另外14个连两层原必要条件筛选后可供精确评估的候选都没有。

这意味着：**大多数失败源结构的首要瓶颈仍是生成能够通过两层必要条件的合法离散候选；只有极少数进入第三层，才谈得上“为什么完整连续分配失败”。**

## 二、严格隔离四个连续资源反事实

在离散路径、上传接触、卸载模式、任务顺序及全部强制 FIFO/EDF 均完全冻结的前提下：

| 模式 | 放松什么 | 哪些保持原硬约束 | 使用目的 |
|---|---|---|---|
| `qos_only` | task deadline、平均时延、UAV周期与电量 | MEC CPU/带宽容量、上传、FIFO/EDF等 | 量化期限/资源约束互相制约 |
| `mec_capacity_only` | 各 MEC CPU **及** 带宽总容量 | 原真实QoS、FIFO/EDF、上传等 | 判断假想容量增加能否恢复固定D |
| `cpu_capacity_only` | **仅MEC CPU总容量** | 原带宽、原时限、原电池、FIFO/EDF等 | 隔离算力上限约束 |
| `bandwidth_capacity_only` | **仅MEC带宽总容量** | 原CPU、原时限、原电池、FIFO/EDF等 | 隔离共享上传资源约束 |

诊断要求 `optimal` 且全部剩余硬约束与松弛约束的归一化残差满足冻结可信门槛；`optimal_inaccurate` 只归入**数值不确定**，不能当作数学无解证明。

| 四个模式在6个原Stage-1失败候选上的结果 | 可信正松弛 | 可信近零松弛 | 不确定 |
|---|---:|---:|---:|
| QoS松弛、原容量保持硬约束 | **6/6** | 0 | 0 |
| MEC CPU+带宽一起假想扩容 | **6/6** | 0 | 0 |
| **仅MEC CPU假想扩容** | **6/6** | 0 | 0 |
| **仅MEC带宽假想扩容** | **5/6** | 0 | **1/6 `optimal_inaccurate`** |

原本 Stage1 严格合格的原始对照结构每个场景选一个，共4个控制；四种模式**16/16**均可信 `optimal`，最小松弛量接近0，无虚构冲突。

**重要解释：** “仅扩 CPU可在软化模型下恢复固定 D”和“仅扩带宽也可能恢复固定 D”是**两个不同反事实**，表明计算与通信到达时序具有可替代的耦合效果；绝不能理解为仅CPU限制是唯一原因，也不能把标准化的最小松弛量直接比较为经济/能耗成本。

## 三、S91 的直接证据：旧两项必要界虽通过，完整资源仍不可行

S91 / K80 / compute×1.5 / A128 的三个候选均通过旧 FIFO/EDF 乐观时间必要界、P2共享静态CPU份额必要界，原 Stage1却全部 `infeasible`。

| 候选终步 | E2 最小静态CPU需求/容量下界 | 可信 QoS 松弛主要任务 | 仅增CPU硬QoS反事实 | 仅增带宽硬QoS反事实 |
|---|---:|---|---|---|
| S17→接触 `G_U5_1`（结构1） | **0.95078** | S3约差 **1.367 s** | E2 CPU额外 **0.134 GHz** | E2带宽额外 **0.576 MHz** |
| S17→接触 `G_U5_2` | **0.89939** | S17约差 **1.544 s** | E2 CPU额外 **0.355 GHz** | E2带宽额外 **0.730 MHz** |
| S17→接触 `G_U5_1`（结构2，不同哈希） | **0.95078** | S36约差 **4.420 s**，另含S3等 | E1 CPU约 **0.371 GHz** + E2 CPU约 **0.134 GHz** | `optimal_inaccurate`，数值不确定 |

第三个候选最后一步名称与第一个相同，但由不同父搜索结构产生，所以原始哈希不同；不能混成一条记录。上表的正松弛是**加权凸弹性反事实的具体物理解**，不是严格的最小不可行约束集或对原固定D的充分定理。

此外 S91 / deadline×0.9 / A128 一个新接触候选：
- 旧必要界中E1静态CPU需求比例已达**0.99782**，但仍通过必要条件。
- `qos_only` 发现 S15、S33等任务有正时限松弛，最大约5.661秒。
- 假想CPU-only再增E1约 **0.807 GHz** 时可保持原硬 QoS；
- 假想bandwidth-only返回高达E1约338.623MHz、E2约120.269MHz的额外带宽需求（远超原资源量），只具有数学反事实意义，不是现实网络扩容建议。

## 四、S89：资源临界点也存在“必要界通过、原Stage1失败”

S89 / deadline×0.9 / A128 的两个候选：
- 原P2静态CPU份额必要界 E1 需求/容量比例约 **0.93626**、**0.88182**，均低于1。
- 原 Stage1均 `infeasible`，完整 QoS 弹性诊断在S57任务上分别需要约2.680s和1.713s的时限松弛。
- 仅CPU容量扩张反事实分别为E1约**+1.704 GHz**与**+0.942 GHz**；仅带宽容量反事实分别为E1约**+12.627 MHz**与**+7.934 MHz**。

这说明原 P2 必要CPU界使用每条虚拟队列的**最乐观首批上传到达时间**（隐含充分给予每条队列全部站点带宽），再把各队列必要CPU求和，能够安全排除部分D，却可能低估“实际带宽共享导致的上传迟到—计算时间窗收缩—所需CPU上升”。通过必要界绝不保证原完整资源可行。

## 五、机制研究方向和不可越过的结论边界

### 根因分层（已有证据）

A. **17个原始失败源中的14个**：各种邻域在当前限制内没有送出可进入CVX的候选，优先研究采集顺序/到达/接触位置与 FIFO/EDF 时间窗口的联合重排。继续只调连续资源评分难以帮助这类源。

B. **6个去重候选均已通过两个必要条件，却原Stage1不可行**：单独的极乐观时间界与静态CPU界有交互盲区；共享带宽分配及其对批次到达时间的影响会改变最低CPU需求。

C. **即便做出更强的必要界，也不能直接给出算法严格恢复**：最多证明额外排除无效结构或释放有限CVX名额。真正的ALNS创新还要通过证书提示 **改哪个接触、何时插入、迁走哪条队列中的何个绑定任务**，并经相同端到端预算和新的从未观察实例验证。

### 更值得验证的可证伪假设

**与其继续孤立地优化CPU下界，不如研究“带宽共享—MEC批次到达—静态CPU最低份额”联合必要可行性判定和候选评分。** 例如对每个固定UAV-MEC对，根据可行带宽份额 `b_(u,e)` 推出不能更早的上传完成时间，再从其强制FIFO/EDF任务前缀求出随带宽变化的 `F_(u,e)^LB(b_(u,e))`；在所有MEC约束 `Σ b_(u,e) ≤ B_e` 下判定是否仍无 `Σ F_(u,e)^LB(b_(u,e)) ≤ F_e` 的可能。这有望更准确识别“两个单独必要界各自通过但真实带宽/CPU无法同时满足”的结构。不过需要重新严格证明该下界对原 P1-R 始终乐观，不能直接把启发式数值求解器的 `infeasible` 当成严格数学证书。

文献创新性边界：
- Cang et al. (2024), [Joint User Scheduling and Computing Resource Allocation Optimization in Asynchronous Mobile Edge Computing Networks](https://arxiv.org/abs/2401.11377) 已将异步任务到达、资源分配与调度用广义Benders分解，并包含可行性割；我们尚未构造Benders方法。其CPU份额是时变，**不能把其数学结论直接用于原论文静态份额界**。
- Karademir et al., EJOR (2025), [A two-echelon multi-trip vehicle routing problem with synchronization](https://doi.org/10.1016/j.ejor.2024.10.047) 已展示路由、同步和容量约束的分解优化；单纯“路径+资源约束反馈”不是空白。
- 不要将“弹性诊断的最大松弛量”当成真实动作的因果增益，也不应把本组4个已观察场景当新独立数据。

**截至本轮不合并 P4 到 `develop`，不修改 ESI-ALNS 论文基准。此阶段以可靠的根因定位为结论，不把物理资源反事实增配作为改进算法性能。**
