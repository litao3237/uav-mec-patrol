# Stage-2数值故障分析与固定结构复验

## 原实验故障

源实验为[36382512068](https://github.com/litao3237/uav-mec-patrol/actions/runs/36382512068)，固定代码`d83a282`。528条记录全部执行，Stage-1合格441条，两阶段合格216条；剩余225条Stage-1合格记录在Stage-2失败。其中108条返回`optimal`但独立残差不合格，117条为`optimal_inaccurate`。多数涉及上传时长、MEC完成时间及重建后任务期限，亦有带宽超限。

原实现的Stage-2只核对资源变量的非负/下界，没有检查完整物理残差便采用求解结果；Stage-2失败回退时，部分最终时延诊断仍读取失败模型残留值。论文统计的独立核验器已挡住这些记录，因此历史216条合格数没有被虚增。

数值原因由冻结实例/方案复现：高信噪比接触的gamma可约为10060 MHz，而带宽约为4 MHz；原`-rel_entr(b,b+gamma)`指数锥与速率倒数嵌套，叠加仅约0.1–0.2 J的能耗容差，导致内点法数值退化、SCS残差超限。简单增加目标权重或改变能耗约束尺度不能稳定恢复所有代表规模。

## 等价修复

仅Stage-2构建无量纲模型，Stage-1搜索评价仍使用原模型、原默认参数与原目标。带宽/CPU按容量缩放，事件时刻按周期缩放，上传时间按满带宽最短上传时长缩放。所有返回值仍是秒、MHz、GHz和J。

令x=b/B、g=gamma/B，使用严格恒等式`-rel_entr(x,x+g)=x ln(g)-rel_entr(x,1+x/g)`，避免高SNR产生很大的指数锥参数。上传约束`tau >= D/R(b)`等价改写为`inv_pos(tau/t_min) <= R(b)/R_max`，其中`t_min=D/R_max`；消除对指数锥输出再取倒数的嵌套。Stage-2能耗约束除以1000，以kJ表示；没有修改原能耗上限。

CLARABEL使用明确的1e-9求解容差；固定备用正目标尺度100，不改变最优解；发生数值退化时缩短内点法步长。固定重试顺序为(目标尺度,最大步长)=(1,0.99)、(100,0.99)、(1,0.95)、(1,0.8)、(100,0.8)，仍失败再尝试其他已安装求解器。每次均独立检查原始变量与重建时序，只有`optimal`且两套残差合格才接受。失败保留求解状态、错误、迭代数、步长与残差摘要；Stage-1回退仍可返回，但不称Stage-2成功。最终时延/回程诊断改从实际返回快照计算。

## 验证协议

六个规模各选取一条旧失败记录验证了等价缩放方向；另将K80/S45/A101原实例、方案、Stage-1变量和能耗锚点作为回归夹具。测试覆盖速率约束边界等价、原高负载失败恢复、`optimal`但残差不合格时禁止替换Stage-1，以及Stage-1搜索不调用Stage-2修复。

全矩阵复验入口`experiments/replay_multiscale_stage2.py`绑定原汇总SHA256与逐源文件SHA256，固定全部528条原方法记录的实例、方案、Stage-1原始变量/对偶/能耗和容差。对441条Stage-1合格记录重算Stage-2，包括原本成功的216条；原87条Stage-1未合格记录保留并跳过，不偷偷修改锚点。先前失败、修复新增成功以及退化记录全部报告。

复验由`.github/workflows/stage2_recovery.yml`在六个规模并行执行；不是重新搜索，不构成新独立场景。保存复算时间，禁止把旧runner的搜索时间与新runner的资源时间拼成端到端速度结论。结果按原场景等权/运行等权及共同有效子集口径重新汇总。

能耗相对容差仍为1e-6，原独立物理残差容差不变。不将`optimal_inaccurate`重新标为`optimal`，不裁剪变量掩盖违约。修复后的高负载比较仍可能受原Stage-1有效场景少的限制，不能保证全部算法都有充分共同样本。
