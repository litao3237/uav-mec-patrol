# P6b S97–S100 首用独立验证：整批 MEC 接触改站不提高严格恢复

**GitHub Actions [38209345803](https://github.com/litao3237/uav-mec-patrol/actions/runs/38209345803)** 于2026-10-12完成，validate、四个先前未用的S97–S100物理场景与summarize **全部成功**、异常0。执行冻结提交 `09cd6722bee5c3a45d9189f8c4d126c8fb40c069`，未根据独立结果修改策略、参数或物理模型。原 `develop` 保持SHA `0bdf3a26d4c042e13f96f84977261ffdd33cfc89`；本分支只新增报告，不允许把本次S97–S100后续重复研究再次称为新独立holdout。

## 1. 冻结试验及来源身份

4个独立物理空间场景、2个**嵌套**算法随机种子A133/A134、K80、四种高压力工况，全部 **32个原 B-ALNS 物理压力状态**；其中 **24/32** 原 Stage1返回 `infeasible_precheck`，严格按事先规则进入相同源 D 配对条件性修复。其余8个原状态：7个 `optimal`、1个 `optimal_inaccurate`，全部在原始源记录中保留且不偷偷算进失败修复分母。

五个候选筛选/批次改站方案全部共享同一原100迭代 B/ESI 源、原原子beam宽2深度4、原P5联合BW/CPU 48格安全必要检查，后续结构动作仅限在**已通过队列必要检查、但联合BW/CPU必要证书拒绝的D**上将原物理MEC contact 改到另一站点。每臂仍最多3个原Stage1 CVX精确候选评价以及原Stage1+Stage2双重残差严格验收。原B探索搜索时间**预付**，故只比较**失败D的条件性修复**，绝非全部 ALNS 等端到端预算实验。

## 3. 把“必要通过候选数量”与“真正有助严格成功”彻底区分

本次P6b `station_all_contacts` 确实构造 **7个新的P5联合必要界通过D**；`joint_binding_pairs_2` 构造4个，字典序构造1个，但这些全部出现在同一个 **S99/compute×2/A134** 源 D。该源的原P5方法**已经严格恢复成功**，并且原前三个 Stage1 CVX名额已经被成功的旧批次复用候选占满。实验协议为了不挤走既有成功，把原严格候选保留在前三位，新增的7个只是备用候选，未获得额外CVX检查机会，因此本轮**无法据此断言这些新D真实资源严格可行**。

其余23个条件修复源 D **没有**产生新联合必要通过D，因此不能寄希望于单纯调增新增候选的排名解决普遍可行性难题。

## 4. 决策：停止强化 post-hoc 整批枚举，转向原 ALNS 搜索生成层

P6b 实验明确反驳了“只要扩大到超载MEC全部上传接触、对接触整批改站，就能显著提高高压力场景恢复率”的泛化假设。**停止继续扩大 batch sweep/加深beam/多CVX名额；不合并到 `develop`，不修改论文能耗和可行性结论。**

关联P7 [原B探索只读轨迹复核](https://github.com/litao3237/uav-mec-patrol/blob/experiment/p7-alns-exploration-feasibility-audit/docs/p7-alns-shadow-feasibility-findings.md) 中，6个原终点precheck失败的代表高负载场景里约595个原ALNS结构只有2个通过 FIFO/EDF 队列必要条件、1个通过联合BW/CPU必要检查且原Stage1仍不可行；正常baseline对照95个结构则有23个通过三个必要检查。**绝大多数失败首先是原搜索没有生成适当结构，而不是精确求解短名单没有评价它们。**

因此下一阶段应研究原ALNS/初始解在80任务多UAV下的 **采集时序、FIFO/EDF队列结构与deadline必要超额的搜索引导**，而不是再堆积源D的后处理邻域。研究需配对同初始解/相同物理场景，对比原proxy、队列违约优先以及任务访问次序重组在**真实相同墙钟总预算下**的严格Stage1+Stage2合格率和能耗；如有机制成功再冻结到完全未见场景验证。

本负面结果全部以独立物理场景为单位，不把不同算法随机种子当成独立空间场景。
