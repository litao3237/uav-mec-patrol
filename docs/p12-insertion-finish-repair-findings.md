# P12 原始任务插入评分与 MEC 重构：同源反事实验证报告（2026-10-12）

**科学问题：** 原 `_insertion_option()` 用单个任务的乐观计算时限、路线周期和增量距离排序，但 `_finish_repair()` 才在完整路线后贪婪重建 MEC 接触/卸载结构。这种分阶段评价是否实际错过 FIFO/EDF 与共享 MEC 资源下严格可行的重插入位置？

**原始证据：** [GitHub Actions #38250211961](https://github.com/litao3237/uav-mec-patrol/actions/runs/38250211961)。`validate`、5个已见场景、`summarize` **全部 success**，共6个冻结原B-ALNS D、12个单任务删除重插入试验和12条真正多任务 ALNS `cheapest`/`regret2` 修复链，异常0。原源 `content_hash`、物理实例 SHA、Route/TaskDecision/真实 Stage1/Stage2 全部保持原口径。仅在 `experiment/p12-insertion-finish-repair-audit` 保存代码与报告，不修改 `develop`。

> **不可误用：** S89、S91、S93、S95、S96 已用于以前算法诊断，**这不是独立新场景检验**；单任务实验选择的每个原插入位置中只抽取固定12个排名（一定包括 rank1，原合法位置约90–97），**不能当作穷举所有位置或全ALNS新算法改善**。对1个目标任务最多3条额外 Stage1 CVX +必要的独立Stage2，属于**事后有偿诊断**，不是原ALNS匹配搜索时间内取得的成果。

## 一、原函数逐行确认：真实比较的究竟是什么

`src/uav_mec/algorithms/alns/operators.py`：
- `_insertion_option` 排序字典序为 `(cycle_overflow_s, deadline_lb_violation_s, delta_distance_m, route_task_count, uav_id, position)`。`deadline_lb_violation_s` 只检查被插入任务**采集完成 + 该任务单独占用全系统最快单CPU的计算时间**；**不计算**该候选对其他任务的 FIFO/EDF 排队后果或未来完整 MEC 卸载变化。
- `_options_for_task` 对所有UAV全部合法插入位置应用该键排序；`cheapest_insertion_repair` 取全局最便宜局部选项，而 `regret2` 利用前两选项的差值决定先恢复哪个任务。
- `_apply_local_insertion` 先把被恢复任务设为 **LOCAL**，只恢复路线/任务决策。
- `_finish_repair` 在所有任务重新插入后，才调用原 `build_mec_assisted_initial_solution(instance,base_solution=state.solution)`，该函数依据另一个完整近似资源代理选择接触复用、新接触和任务卸载；最后只用旧完整原物理模型独立评估严格可行性。

**确认：原插入评分与最后完成的 MEC 结构确实不是同一个时序模型；但不能仅因模型层级不同就断言有bug，必须看反事实证据。**

## 二、同一原始 D、同一被删除任务、同一个旧 MEC 重建函数的12组定向反事实

6个冻结B状态中每个从最紧必要时间违约任务选择一项，再补一个不同的原计算模式（LOCAL/OFFLOAD），原`_destroy_tasks`只移除这一项；再调用**原封不动的`_options_for_task`**获得**完整原排序**，评估排名前6与按原排名均匀抽样的其它6个位置，合计**144个完整合法候选**。对每个候选固定位置做 `_apply_local_insertion`，检查全部80任务的乐观 FIFO/EDF 必要时序；接着运行**原封不动的`_finish_repair`**，再次测量。这保证候选仅在选择相同任务的不同插入位置上变化，后续 MEC 修复代码完全相同。

| 指标 | 实验值 |
|---|---:|
| 冻结独立源D（含S93同场景不同profile） | **6** |
| 删除单任务测试 | **12** |
| 原合法插入位置中按预设排名抽样 | **144** |
| 原排序第1位被后续**已抽样**位置在全任务队列必要指标上明显超过 | **10/12** |
| 原排序第1位 FIFO/EDF 必要失败，而后续已抽样位置通过 | **1/12** |
| `_finish_repair` 实际改变卸载/接触等物理离散决策 | **72/144** |
| 原单任务重插入候选中必要时序通过：MEC修复前 → MEC修复后 | **3 → 12** |
| `_finish_repair`使候选必要违约理由数减少/增加/不变 | **57/3/84** |
| 对原rank1、最优已采样rank及修复前rank1进行额外原Stage1/Stage2 | 每个源第一任务≤3个不同结构 |

**第一层判断：** 原插入字典序在强压力的10/12项中未优先选出本实验中真正队列指标较好的位置。这是**局部代理排序与完整固定D队列必要约束不一致**的实验证据，而非原整个ALNS已经被证明可由一个新评分稳定改善。

**第二层判断：** 原`_finish_repair`总体**倾向于改善**，并非普遍损害队列必要可行性：144样本中57项减少必要约束理由、9个此前必要失败结构经重建后变为必要通过，0项由通过变失败。只有3项总违规理由数增加（即使总体任务deadline秒数有时下降）；不能笼统说函数本身“有bug”或MEC重构总是变差。

## 三、核心严格可行反事实：S96 deadline×0.9 / A130 / S23

源是**原B-ALNS的固定失败离散D**，任务 S23 原决策为LOCAL。把**完全相同**的 S23 删除后：

| 完全相同的任务、源D与原 `_finish_repair` | 旧 `_insertion_option` 第1位 | 旧 `_insertion_option` 第3位 |
|---|---|---|
| 恢复无人机/路线位置 | **U4第16位** | **U5第15位** |
| 原判定周期超期 | 0s | 0s |
| 原判定单任务deadline乐观违约 | 0s | 0s |
| 新增飞行距离 | **0.257m** | **18.130m** |
| 完成整个本地恢复、MEC重建前所有任务必要超时总和 | **3.905s** | **39.856s** |
| 原 `_finish_repair` 接触/卸载动作 | **0次，不改变结构** | **1次，S23复用现有接触 `G_U5_2`由LOCAL改为OFFLOAD** |
| 完成原 MEC 重建后必要任务总超期 | **3.905s** | **0s** |
| 原 Stage1 数值/严格资格 | `infeasible_precheck` /失败 | **`optimal` /严格合格** |
| 原 Stage2 完整独立残差资格 | 跳过，不合格 | **严格合格** |
| 最终能耗 | 原方案严格不可行，禁止报能耗 | **267390.475 J** |

**因果结论：** 原旧插入评分的两个最优先级（周期/单任务deadline）对这两位置都给出0违约，故按距离把 U4 第16位排第一；但这使后续MEC重建不采取动作，保留原队列冲突。旧排名第三的 U5 第15位虽然路径多约17.87m，**可触发原 MEC 接触复用**，使该固定源D从乐观必要失败变为原严格 Stage1+Stage2完全合格。

更微妙的是：**在 MEC 修复前，第三位本地计算结构的乐观总超时39.856s反而比第一位3.905s糟糕**，但经过相同原MEC重建后排序逆转。因此既不能只使用原独立单任务评分，也不能简单在**尚未做MEC重建前**按队列时限评分就保证选到严格可行位置。真正值得研究的机制必须考虑：**一个重插入位置对可用MEC接触复用/批次安排的后续可操作性**。

这是可追溯的**真实严格可行结构**，但属于一次已观察开发样本的**额外事后精确评价**，不能说P12替代原ESI算法后成功率已提升，也不能把这个原本不可行的B端点与267390.475J做能耗差比较。

## 四、真正原ALNS的12任务 destroy → cheapest/regret2 → 原MEC修复链

为了避免仅用单任务实验误读实际ALNS，本轮另用原 `DestroyConfig` 从6个冻结完整D各移除**12/80个任务**，分别运行**原 `cheapest_insertion_repair` 与原 `regret2_insertion_repair`**；只读spy记录`_finish_repair`入口**全部任务先LOCAL插好后的完成结构**和出口的真实完整MEC结构。全部原运算子、固定随机seed、原重构函数不变。

| 指标 | 真实结果 |
|---|---:|
| 完整12任务删除+修复运行 | **12次** |
| MEC重构后 queue 必要违反理由数下降 | **12/12** |
| MEC重构后 queue 必要违反理由数上升 | **0/12** |
| 仅凭MEC重构即新增完成原Stage1+Stage2严格合格 | **未作为算法比较测量/不可宣称** |

例如S91 compute×1.5/A128：
- cheapest：重构前队列必要违约理由 **14项**，原MEC重构后 **2项**；
- regret2：重构前 **15项**，重构后 **3项**；两者都仍违反必要条件，不能判为严格可行。

由此**进一步排除**“真正主要问题是`_finish_repair`一概把正确的任务路线变坏”的过强假设。它能够改善大量时限冲突，但**插入评分没有预判这种重构可行的路线潜力，也无法保证最终做到所有任务联合严格合格**。

## 五、性能成本与下一步实验应该如何设计

144个候选原 MEC 重建单次平均约 **0.069s**，95分位约0.132s，最长0.263s，总计约10秒（各Windows runner的量测总和）；原整个12任务 cheapest/regret2 修复运行平均约0.509s。因此对每个ALNS每次任务插入做全局80–100个位置的 **MEC全量重建+CVX** 并非免费或可忽略开销，不应以穷举后验Oracle改善偷换原6秒探索+2秒精英预算。

**优先下一步：开发少量候选（例如旧top1外加同站接触复用潜力好的候选）的*轻量结构机会代理*，在任务真实恢复/局部完整结构后执行少数`_finish_repair`预览，再仍由原ALNS/Stage1/Stage2验收判定。** 须至少做四臂因果控制：
1. 原top1插入 + 原MEC修复；
2. 相同额外候选预览名额，但按原飞行距离排序（计算预算负对照）；
3. 相同名额，按**恢复后接触复用可达性**或局部MEC潜力排序；
4. 更严格但耗时更多的预览后queue必要重排上界（仅科研校准，不作为免费主算法）。
任何正向方法必须在**真正相同端到端墙钟预算**下先冻结再在 **S113之后完全未使用的独立物理空间场景**与多个任务规模进行验证。不可将本轮S89–S96、或先前P9/P10使用过的S105–S112再次当新独立样本。

## 结论

**实证确认两函数间存在局部决策错位**：独立单任务+增量距离插入排序不能准确代表后续MEC接触复用与全任务FIFO/EDF耦合后的可行性；本轮首次提供一组严格两阶段成功的复现反例（S96/S23：旧rank1失败、旧rank3成功）。**但`_finish_repair`本身更多是在修复而不是破坏队列必要条件**，不能把问题描述成明确的程序错误。新算法仍未设计、冻结或证明优于原ESI。
