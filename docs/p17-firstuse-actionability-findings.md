# P17 首次独立场景 S121–S124：原 MEC 贪婪动作可采纳性引导插入首次取得正向结果

**证据链：** [P17 首用独立 GitHub Actions #38337720107](https://github.com/litao3237/uav-mec-patrol/actions/runs/38337720107)，`validate`、四个预先冻结的独立物理场景S121–S124、自动`summarize` **全部 success，程序错误0**。冻结提交 `95ef2f34056db26db0b7265d46a9c795f8c84888`，原物理模型与 P1-R/Stage1/Stage2完整残差资格不改，源 `develop` SHA `0bdf3a26d4c042e13f96f84977261ffdd33cfc89` 原样。S121–S124在新机制结果首次查看前方法/参数已冻结，本轮之后不可再将其当“首次未见场景”。研究方案说明：P17开发分支 `docs/p17-actionable-insertion-protocol.md`。

## 一、实验是如何保持因果对照的？

共 **4个独立物理空间场景**×**5个原论文相同的配对单因子profile**×**2个嵌套ALNS算法随机种子169/170**＝40个配对案例（**不是40个独立场景**）。每臂同物理实例、相同原greedy→MEC初始D、原100000上限+探索搜索6秒墙钟目标、原ESI精英2秒目标、相同原破坏算子数/ALNS RRT/roulette/ScreenedProxy目标、原资源CVX Stage1+Stage2和独立残差阈值；相同P7只读FIFO/EDF/P2CPU/P5联合带宽CPU必要指标旁路观察器，其开销也计入6秒探索。**真实数值求解与最终双阶段验收无法被搜索时钟强行抢占，因此6+2秒不是完整端到端硬截断，实际完整耗时独立报告。**

仅替换两个原 repair 算子中**最后一个待插入任务的原Top3位置选择**（其余11项插入决策/次序不变），完整原`_finish_repair`仍只执行一次，不额外调用CVX；四组代价匹配变体：
- `proxy_sham`: 完成全部与新策略相同的廉价原代理打分，但返回原rank1，仅测量额外CPU成本；
- `proxy_contact`: 仅按插入后现有MEC contact数量选择；
- `proxy_critical`: 只按插入任务是否在原`_critical_local_tasks(...8)`且后续有原contact选择；
- `proxy_actionable`: 原rank1的真实代理违反数为0则保留；否则确认原critical8内是否存在接触复用方案满足原`_strictly_better(ProxyScore)`，按原可接纳候选的严格代理key选择Top3插入位置；没有即保留rank1。

**这不是可行性数学充分条件，不保证贪婪构造器最后采用该接触；更不保证原Stage1完整资源可行。只有真实完整双阶段残差合格才记成功。**

**原对新严格配对：**
- `proxy_actionable`在 S121/deadline×0.9/A169、S123/deadline×0.9/A169、S124/compute×1.5/A170 上各 **新增1条完整两阶段严格成功**，**丢失原有严格成功0条**，最终 **7→10/40**（增加3条，若仅按记录比例为17.5%→25.0%，差7.5个百分点，不是已证统计提升）。新增分布在3个不同物理场景，比重复只在一场景更有说服力，但独立场景总数仍仅4。
- `proxy_critical`新增1条却**丢失1条原成功**（S123/deadline×0.9/A170），净0；`proxy_contact`和`proxy_sham`都没有新增且丢失同一个原成功。因此不能把P17增量简单归因为“额外Top3”和“关键任务+有接触”，相反包含 `ProxyScore` 的严格改善条件在本组里具备辨识力。
- 新方法使通过FIFO/EDF和联合BW/CPU必要条件的总新D略增，但**只做必要界通过不算Stage1严格结果**。

**风险和时间成本：** P17完整每案例均值8.626s对旧8.330s，**多0.296s（约3.6%）**；实际ALNS迭代数595对旧610，**少15次（2.46%）**。这远小于P14完整MEC三次预览在类似独立试验中减少约45%迭代的代价。额外低成本代理评分约0.161s/案例，仍不能忽略，整体总时间差还受最后数值资格验收所花的动态CPU时间影响；因此只能叫**匹配探索时钟预算的正向可行性结果**，不是严格同全部运行硬时间预算的证明。

## 三、能耗结果必须同源配对；不能只报条件均值

原与`proxy_actionable` **共同Stage1+Stage2严格合格7条**。严格配对节能（原能耗−新能耗）依次约 **+11920.13J、−6952.90J、−529.96J、−4636.98J、+3370.65J、0J、+243.12J**；总和+3414.07J，平均**+487.72J/共同成功配对**，但正负混杂，4个独立场景且并不保证场景/负载层面的显著节能。

各方案仅有严格成功时的条件能耗均值（原234175J vs新238635J）**成功分母不同（7 vs10），不能直接比较为能耗损失/提升百分比**。**目前不能称P17降低了原ESI能耗**。新增加的3条真实严格结果过去无同源可行结果可与其比较能耗，只能报告各自可行时的绝对能耗。

## 四、对前几轮结果的科学解释

P12 rank1→rank3 S96/S23严格恢复证明原局部插入位置评分存在模型特有错位；P14多次完整MEC重构预览在独立S113–S116从原7/40降到5/40，原因额外预览将搜索迭代732压到401。P15乐观现存contact虚拟卸载在独立S117–S120保留原迭代422对422，但最终严格原10/40、新10/40；其虚拟时间必要通过并不保证原MEC会选择此卸载。P16对原`_critical_local_tasks`和`_strictly_better` 36个已见候选验证原MEC代理候选可采纳性平均3.703ms/候选，原真实全MEC重建73ms/候选；*但候选入池13例只有9例真的成为贪婪第一选择*。P17在相同原代理内部动作逻辑中用便宜筛选引导插入，首用场景确实出现**与模型行为相符、CPU开销受控、尚未损失原成功**的早期正向证据。

**研究创新边界：** 在ALNS中采用快检/时间窗启发式有先例（Liu et al., *EJOR*, 310(1),133–155, DOI 10.1016/j.ejor.2023.02.028），P17如果最终可投稿，新颖性不能依靠“Top3/critical/acceptance评分”普通构件，而应证明：**UAV巡检路径采集→任务本地FIFO及远程EDF/接触FIFO→固定MEC CPU/带宽份额→原贪婪接触复用的操作条件**构成特定模型关联，并用跨场景、跨K、与全ALNS预算、严格残差和资源耦合消融支撑。

## 五、下一步科研验收门槛（没有自动合并 develop）

1. **首个严格匹配全部预算的对照：** 原搜索和新机制均同一真实完整端到端总预算而不是只限 B探索6s、精英2s，再将 CVX资格验收相同口径计费，报告不可抢占求解器例外和真实计算成本。
2. **更多预先冻结且首次未见空间布局**，由空间场景/聚类为统计主单位，而不是把随机种子行全部当iid。场景数4，新增3全严格成功/0损失，普通配对McNemar两侧精确检验不显著（忽略场景聚类也约p=0.25），不能成为普适论文结论。
3. **多个任务尺度**，至少K30/K50/K80，并且包含原论文常规能耗优势依赖的低压力场景而非只研究高压恢复；严格两阶段可行率和条件同源能耗同步评估。
4. **关键算法消融**：`proxy_contact`、`proxy_critical`、`proxy_sham`目前都包含，仍需在不同空间布局确认“真正的原MEC改善接受条件”而非特定种子偶然贡献；检查有限几个受MEC资源约束支配的失败源修复，避免只追逐少数期限边界。
5. 如果进一步证据弱或原成功被破坏，不要合并论文主算法、不要事后调参反复使用S121–S124直到得出正向结果。**当前只能说P17是到目前最值得做扩大验证的候选机制，不是已获稳定学术显著改进。**
