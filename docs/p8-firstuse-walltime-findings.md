## 1. 冻结协议与事实局限

4个不同物理场景，每个场景5个配对物理工况（正常、计算×1.5、计算×2、期限×0.9、期限×0.8），每工况两个嵌套算法随机种子137/138，共40组配对 `原ALNS`、`queue_sum`、`queue_max`。各组使用**完全相同的初始离散解、ALNS随机种子、原destroy/repair和精英强化算子**；改变的是探索过程的队列必要超额连续惩罚函数。

每组探索阶段原 `MaxRuntime=6s`（墙钟规则）且时变RRT以相同冷却时钟推进；精英期最多2秒上限；同一个原Stage1、Stage2独立残差和能耗验收。**并非完全严格的整流程绝对6+2s硬停止**，因此所有运行都独立保存了真实探索时长、精英期时长、原连续资源重算、Stage1/2验收和完整总时间；不同结构在终态的数值验收成本不同。对每个ALNS新访问的D加**同一个只读P7 shadow观察器**；此真实观察器开销计入6s搜索预算，不参与搜索目标/接受决策。成功按原Stage1与Stage2都严格合格，不把必要条件通过当真正成功。

### 严格能耗必须按同源双合格配对

共同严格合格的5个配对案例内：
- `queue_sum` 相对原ESI有两个能耗完全不变，S102 deadline×0.9/A137改善约1291.44J，但S103 baseline/A137**损失约7410.48J**、S103 baseline/A138**损失约836.39J**；
- `queue_max` 两个完全不变、同样一个改善1291.44J，但S103 baseline/A137损失约7410.48J，另一个配对相同。
- 把每臂不同的“只在严格合格条件下取平均能耗”直接相减会受到可行样本组成影响，**不能**用于宣称全算法能耗优势。本数据的严格配对能耗也没有稳定改进迹象。

## 3. 研究决策

1. **正式拒绝 P8“队列乐观下界违约罚分直接取代原ALNS标量评分”作为论文主算法方向**。开发样本和首次独立场景共同观察到无严格可行性提升/有正常工况原成功损失，且没有显示可重复能耗收益。
2. 这是“局部目标函数缺少有效可操作邻域”的模型证据：在给定原destroy/repair结构下，只告诉ALNS哪类时限违反得更重，未必能产生必须同时调整的路径/采集/接触顺序，甚至可能把搜寻引向更少必要可行的区域。
3. 下一阶段应**只修改原ALNS的一类生成动作，并保留旧评价函数**作为隔离消融，而不是增加新算子数量：例如将原 `critical_task_removal` 一换一替换为FIFO/EDF期限违约任务/直接阻塞前驱选择，对照全局最高计算负载选任务，保持原 greedy/regret2 repair、物理模型与真正全流程墙钟预算不变。需要在已观察场景开发后再另用首用场景验证。
4. 新S101–S104从现在起已经用于P8判定，今后如果调P9/P10就属于研发数据，不得将S101–S104重复称为首次独立holdout。

**原始研究分支保持不变；本报告拒绝用相同迭代开发样本或少数配对能耗偶然改善夸大论文创新性。**
